# Documentation map

> What lives where in Crema's documentation.
>
> GitHub Pages publishes `/docs` from `main`; the site's homepage is
> `index.html`, which superseded this file there. This map is what you read
> when browsing the repository on GitHub. Repository links below stay
> absolute — relative links like `../README.md` would break anywhere Pages
> renders this file outside the repository tree.

## Repository root

- [README.md](https://github.com/colatte/crema/blob/main/README.md) — public overview: what Crema is, installation, usage, license.
- [ROADMAP.md](https://github.com/colatte/crema/blob/main/ROADMAP.md) — directions and possibilities; not promises, not dated commitments.
- [CONTRIBUTING.md](https://github.com/colatte/crema/blob/main/CONTRIBUTING.md) — how to contribute.
- [CLAUDE.md](https://github.com/colatte/crema/blob/main/CLAUDE.md) — the contract, in Portuguese, for how code is written in this repository: architecture, conventions, concurrency, and the rules the layers live by. Read at the start of every working session; evolves with the code.
- [LICENSE](https://github.com/colatte/crema/blob/main/LICENSE) — GPL-3.0.

## docs/

- [index.html](https://github.com/colatte/crema/blob/main/docs/index.html) — the homepage GitHub Pages serves: a static, self-contained landing page. Its media lives in `assets/` and `assets/video/`.
- [DECISIONS.md](https://github.com/colatte/crema/blob/main/docs/DECISIONS.md) — design memory: the load-bearing decisions behind the fragile parts of the system, plus bug-class jurisprudence. Code comments cite its anchors as `(docs/DECISIONS.md: <anchor>)` but always carry the lesson themselves; the anchor is a pointer for depth.
- [ACCEPTANCE.md](https://github.com/colatte/crema/blob/main/docs/ACCEPTANCE.md) — the 19 acceptance criteria: the observable definition of "the app is correct", each one checkable on a running Crema.
- [RELEASE-GUIDE.md](https://github.com/colatte/crema/blob/main/docs/RELEASE-GUIDE.md) — how a release is built, signed, packaged and published, and how the Sparkle update cycle is fed — including the one-time backup of the EdDSA private key, whose loss would end the update channel for every installation.
- [LOCKSCREEN-INVESTIGATION.md](https://github.com/colatte/crema/blob/main/docs/LOCKSCREEN-INVESTIGATION.md) — the closed investigation proving on hardware that no window level composites over the lock shield; it is the evidence behind lock-aware suppression, and three code comments cite it.
- [system-contact-inventory.md](https://github.com/colatte/crema/blob/main/docs/system-contact-inventory.md) — the ~90 places the app touches a resource that can die underneath it, in five classes. A checklist for future review; its statuses are dated and must be re-verified before they are trusted.
- [design-reference.md](https://github.com/colatte/crema/blob/main/docs/design-reference.md) — research, in Portuguese: visual styles and polish that inform the notch/card/classic skins. Values are starting points to calibrate on hardware, not absolutes.
- `assets/` — the images and motion published with the docs: the showcase screenshots and the two animated GIFs the README embeds (`crema-hero.gif`, `crema-style-switch.gif`), the landing page's HUD specimens (`hud-notch.png`, `hud-card.png`, `hud-classic.png`), the web export of the app icon, the README's download badge (`download-macos.png`, generated by `design/badge/makedownloadbadge.swift` — regenerate there, never edit by hand), and `video/` with the teaser the landing page plays (`crema-teaser.mp4` plus its poster). Two captures are kept for reference that no page links yet — the notch at rest (`notch-compact.png`) and the Settings window (`settings-about.png`); naming them here is what keeps a future sweep from reading them as litter.
- [osd-suppression-reference.md](https://github.com/colatte/crema/blob/main/docs/osd-suppression-reference.md) — research, in Portuguese: suppressing the native volume/brightness OSD — techniques surveyed, constraints (reversible, opt-in, no SIP changes) and discarded paths.
- [appcast.xml](appcast.xml) — the live Sparkle update feed, served by GitHub Pages (/docs from main). `scripts/release.sh` regenerates it on every release, and the file is never touched by hand: each enclosure needs an EdDSA signature only the release tooling produces, and the feed itself is signed, so an edit after generation is an outage rather than a mess (docs/DECISIONS.md: the-feed-signs-itself).
- `internal/` — gitignored, local-only working docs (the specification, the plan, and working audits). Everything in there that a code comment or an outside reader needed has been distilled into the files above; the cited lesson is always restated where it is cited, so readers without this folder lose depth, never meaning.

## scripts/

- [release.sh](https://github.com/colatte/crema/blob/main/scripts/release.sh) — the release: build, build-number stamp, signing (ad-hoc / self-signed / Developer ID + notarization), dmg, and the appcast regeneration. It commits nothing.
- [check-catalog.py](https://github.com/colatte/crema/blob/main/scripts/check-catalog.py) and [check-catalog-selftest.py](https://github.com/colatte/crema/blob/main/scripts/check-catalog-selftest.py) — the String Catalog gate, plus the self-test that proves the gate still fails on every rule it claims to enforce. Both run in CI; Xcode enforces none of it.
- `probes/` — standalone hardware probes (`swift scripts/probes/<name>.swift`). Each one decides a question no unit test can answer — is the neighbour publishing, does a held media key repeat, does one keypress move two displays — and each carries a control that makes a negative result mean something. They are instruments, not part of the app or of CI.
